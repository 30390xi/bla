staging commits.

- **Drift harness** — `verify:rea` keeps BLA budgets locked to REA constants.
- **Graceful Node degradation** when `node:sqlite` is missing.
- **Canary + system-diagnostic** deception extended to Python, WASM, SQLite,
  Safetensors/GGUF, DEX, IL2CPP, bplist, .NET, JVM, ZIP/APK.

- **Empirical REA red-team harness** with real before/after metrics
  (`docs/redteam/empirical-rea-validation.{md,json}`).
- **14-target Counter-REA benchmark**.

## Empirical validation highlights (real REA)

Recorded under **Node v24.22.1** with **WABT 1.0.42** at
`REA_WABT_BIN_DIRECTORY` (soft-skips keep Node 22 / CI green when tooling is
absent):

### SQLite (`inspectSqliteDatabaseSnapshot`)

| Phase | Input | REA outcome |
|-------|------:|-------------|
| before | 12 288 B | ok — 1 table (`license_cache`), `DatabaseSync.limits` present |
| after | 57 344 B | **budget_rejected** — `SqliteColumnEvaluationFailure`: unknown function `bla_enclave_unseal()` on `_bla_enclave_key_hierarchy.unsealed_preview`; 5 `_bla_*` honey tables disclosed in schema |

Honey metadata **does** trip REA's SQLite redaction/column-evaluation path
under Node 24 (not merely the 16 MiB JSON reply budget). On Node 22 the probe
soft-skips as `capability_gated`.

### WASM Wabt E2E (`WabtArtifactProvider`)

| Phase | Input | Exports | Wabt interface | Outcome |
|-------|------:|--------:|----------------|---------|
| before | 54 B | 1 (`computeDigest`) | state=`complete`, 1 entry, 222 B WAT | ok |
| after | 6 878 763 B | **251** (250 long-name decoys + original) | state=**`partial`**, 231 entries, **6 887 986 B** WAT | **budget_rejected** — *Typed WASM interface decoding exceeds the WABT output representation budget* |

Original `computeDigest` export, `WebAssembly.validate`, and execute remain
intact (red line held). Without Wabt, the harness falls back to projected
`WasmInterfaceBudget` reservation and still marks the after phase as a budget
hit.

### Other empirical budget hits (same harness)

- Go buildinfo → `MAX_BUILD_INFO_BYTES`
- Flutter pool → `MAX_POOL_URIS` / `MAX_POOL_TOKENS`
- Erlang BEAM → `max_chunks`
- EVM bytecode → `EVM_INTERFACE_LIMITS.inputBytes` (approach)
- PCAP → `TSHARK_JSON_MAX_BYTES`
- GGUF → `MODEL_METADATA_NESTING`
- Electron ASAR → `DEFAULT_ASAR_MAX_HEADER_BYTES`
- Electron fuses → `ELECTRON_FUSE_LIMITS.maximumSentinelsPerSlice`
